## 3) 계획 대비 달라진 구현 방식

### 3.1 HITL 위치

34번 문서는 handoff 중심이지만 실제 supervisor 구조와 결합해서 보면 중요한 차이가 있다.

- 현재 HITL은 graph 내부 노드가 아니라 `SupervisorAgentService` 사전 게이트다.
- 따라서 handoff는 "HITL 이후 실행되는 graph 분기"로 동작한다.

### 3.2 Swarm 동시성 제어

이전 문서/리뷰 시점보다 현재 구현은 더 진전되었다.

- `DefaultSupervisorSwarmCoordinator`가 `upsertWithRetry(...)`를 사용
- version conflict 발생 시 최신 상태 기반 재계산 후 재시도

즉, handoff fact 갱신의 충돌 처리 부재 문제는 현재 구현에서 상당 부분 해소되었다.

## 4) 아직 남아있는 제한

### 4.1 진행 이벤트의 사용자 노출 일관성

handoff는 내부 event log에서는 잘 기록되지만, 사용자에게 전달되는 progress 스트림에서 항상 별도 line으로 분리되어 보장되지는 않는다.

현재 구조:

- orchestrator는 초기/compose/complete/error 중심 progress를 직접 emit
- graph 내부 node는 swarm event log에 metadata를 기록

따라서 운영 UI에서 handoff를 강하게 드러내려면 graph node metadata를 progress stream으로 승격하는 추가 연결이 필요하다.

### 4.2 문서 34의 일부 문장은 여전히 “미구현” 전제

34번 문서는 계획 문서이므로 다음 항목은 현재와 다르다.

- handoff를 first-class concept으로 다루지 않는다
- SwarmState에 handoff 이력이 없다
- graph에 handoff 분기가 없다

이 문장들은 더 이상 현재 코드 설명으로는 맞지 않는다.

### 4.3 테스트 범위 문서화 보강 여지

관련 테스트는 이미 존재한다.

- `DefaultHandoffPolicyServiceTest`
- `DefaultA2AInvocationServiceTest`
- `SupervisorAgentOrchestratorExecuteTest`
- `SupervisorA2aIntegrationTest`

다만 문서상 어떤 테스트가 어떤 요구사항을 커버하는지 매핑 표는 아직 없다.
